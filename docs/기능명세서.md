### 이 문서와 통합 기능명세서의 관계

- **통합 기능명세서**가 "무엇을 만드는가"(기능, 우선순위, 동작 규칙)를 정한다. 이 문서는 그 규칙을 다시 적지 않는다.
- **이 문서**는 한채가 "어떻게 보이고 어떻게 느껴지는가"(콘셉트, 용어, 화면, 디자인)와 통합 명세 7장의 선택 항목에서 고른 방식을 정한다.
- 기능은 통합 ID(`POST-01` 등)로 가리킨다. 동작 규칙이 궁금하면 통합 명세 6장의 같은 ID를 본다.

## 1. 개요

### 1.1 서비스 소개

| 항목 | 내용 |
| --- | --- |
| 서비스명 | 한채 |
| 한 줄 소개 | 누구나 자기 집 한 채를 짓고, 그 안에 기록을 쌓고, 이웃의 집을 찾아가는 동양풍 블로그 플랫폼 |
| 핵심 콘셉트 | **한 사람이 하나의 집(한채)을 갖고, 그 안에 자신의 기록을 쌓아 간다** |
| 참고 서비스 | 티스토리 (기능 구성), 한옥 (공간 구성) |
| 운영자 | Minju |
| 서비스 형태 | 웹 기반 블로그 플랫폼 (프론트엔드 + 백엔드 서버 + 데이터베이스) |

한채는 블로그의 구조를 **집이라는 공간**으로 다시 풀어낸 블로그 서비스다.

회원은 자기 블로그를 여는 대신 **한채를 짓고**, 그 집의 **주인**이 된다. 한채 안에는 주제별로 **방**이 있고, 글은 방마다 **기록**으로 쌓인다. 다른 사람의 블로그를 보는 일은 **다른 한채에 방문**하는 일이고, 마음에 드는 한채와는 **이웃**을 맺는다. 방문객은 주인에게 **방명록**으로 인사를 남긴다. 그리고 이 모든 한채가 모여 하나의 **마을**을 이룬다. 서비스의 메인 화면이 바로 그 마을이다.

```
                    [ 한채 마을 ]  ← 서비스 메인

     ┌──── 민주의 한채 ────┐        ┌──── 서현의 한채 ────┐
     │  마당 (최근 기록)    │  방문   │  마당 (최근 기록)    │
     │  ├ 개발방           │ ─────▶ │  ├ 기록방           │
     │  ├ 여행방           │  이웃   │  ├ 취미방           │
     │  └ 일상방           │ ◀───── │  └ 생각방           │
     │  방명록             │        │  방명록             │
     └────────────────────┘        └────────────────────┘
```

**한옥 디자인을 입힌 블로그가 아니다.** 티스토리형 블로그의 기능(소셜 로그인, 블로그 개설 · 설정, 글 작성 · 수정 · 삭제, 카테고리 · 태그, 이미지 업로드, 공개 · 비공개, 댓글 · 공감, 구독, 방명록, 검색, 인기 글 · 인기 블로거, 관리자 기능)은 통합 명세 그대로 가져가고, 그 기능을 사용자에게 보여 주는 **언어, 화면 구성, 이동 경험**을 한채의 공간 개념에 맞춘다.

### 1.2 서비스 목적

> 자신만의 한채에 기록을 쌓고, 다른 사람의 한채를 방문하며 다양한 이야기를 발견하고 교류하는 서비스

| 목적 | 설명 | 관련 기능 |
| --- | --- | --- |
| **나만의 집에 기록을 쌓는다** | 한 사람이 한 채를 갖는다. 방(카테고리)과 태그로 기록을 정리하며, 시간이 지날수록 집이 채워지는 감각을 준다 | BLOG, POST, CAT, TAG |
| **다른 한채를 찾아가 발견한다** | 마을(메인)에서 지금 많이 읽히는 기록, 인기 있는 한채, 골목(주제)별 기록, 새 기록을 최대한 많이 보여 준다. "블로그를 검색한다"가 아니라 "다른 사람의 한채를 찾아간다"는 경험으로 만든다 | HOME, SRCH |
| **이웃과 교류한다** | 마음에 드는 한채와 이웃을 맺고 새 기록을 받아 본다. 기록에는 댓글과 공감을, 한채에는 방명록으로 인사를 남긴다 | SUB, CMT, SOC |
| **공간이 있는 경험** | 화면 이동이 `마을 → 대문 → 마당 → 방 → 기록`의 공간 흐름으로 느껴지게 한다. 동양풍 요소는 장식이 아니라 이 흐름을 보여 주는 데 쓴다 | 4장 디자인 방향 |

### 1.3 문서 목적

이 문서는 한채의 각 기능이 **어떤 화면에서, 어떤 이름으로, 어떻게 보이는지**를 정의한다.

- 화면과 UI 문구를 만들 때 기준으로 쓴다.
- 통합 명세의 선택 항목 중 한채가 고른 방식을 밝힌다.
- 통합 명세와 다르게 하는 부분과 그 이유를 남긴다.

### 1.4 대상 사용자

| 사용자 (내부 용어) | 한채에서 부르는 이름 | 설명 |
| --- | --- | --- |
| 비회원 | 나그네 | 로그인하지 않고 마을과 한채를 둘러보는 사용자 |
| 회원 | 마을 사람 | 로그인한 사용자. 댓글, 공감, 이웃 맺기, 방명록을 쓸 수 있다 |
| 블로그 주인 | 주인 | 한채를 지은 회원. 자기 한채의 방, 기록, 방명록, 설정을 관리한다 |
| 서비스 관리자 | 마을 관리인 | 한채 운영자. 회원과 게시물을 관리하고 신고를 처리한다 |

> "나그네", "마을 사람", "마을 관리인"은 안내 문구에서만 쓰는 표현이다. 버튼과 오류 메시지에는 쓰지 않는다 (2.1 원칙 3).

### 1.6 범위

**포함 범위**: 통합 명세 1.2의 13개 영역. 한채에서 어느 단계에 만들지는 6장 기능 목록에 적는다.

**제외 범위**: 통합 명세 1.2의 제외 범위에 더해, 한채가 블로그가 아니라 게임 · 메타버스처럼 보이게 만드는 기능은 넣지 않는다.

| 넣지 않는 기능 | 이유 |
| --- | --- |
| 가구 배치, 집 꾸미기, 방 꾸미기 시스템 | 기록보다 꾸미기가 목적이 된다. 통합 명세 BLOG-05(스킨 · 배경)도 한채에서는 넣지 않는다 |
| 아이템 수집, 재화 | 블로그가 아니라 소셜 게임이 된다 |
| 한채 레벨, 등급 | 기록의 가치를 점수로 매기게 된다 |
| 아바타, 캐릭터 이동 | 짧은 개발 기간에 맞지 않고, 글 읽기를 방해한다 |
| 마을 지도에서 집을 클릭해 들어가는 화면 | 글보다 연출이 앞선다. 마을은 지도가 아니라 **목록과 랭킹**으로 보여 준다 |

**원칙**: 새 기능을 더하지 않고, **블로그를 쓰는 행위 자체가 한채를 쓰는 경험처럼 느껴지게** 만드는 데 집중한다.

## 2. 용어집

### 2.1 원칙

1. **내부는 그대로, 화면만 한채로.** DB 테이블, 코드, API, 통합 명세의 용어(Blog, Post, Category 등)는 바꾸지 않는다. 사용자에게 보이는 화면과 문구에만 한채 용어를 쓴다. 팀 ERD와 통합 명세를 그대로 쓸 수 있고, 내부 용어가 둘로 갈려 헷갈리는 일을 막는다.
2. **공간 이름은 한채 용어, 행동 이름은 익숙한 말.** 화면 제목, 메뉴, 영역 이름(마을, 한채, 방, 마당)은 한채 용어를 쓴다. 버튼처럼 누르면 무언가 일어나는 곳(저장, 삭제, 로그인, 검색)은 누구나 바로 알아듣는 말을 쓰고, 필요하면 한채 용어를 함께 쓴다. 예: "한채 짓기" 버튼은 쓰되, 저장 버튼을 "봉하기"로 바꾸지 않는다.
3. **오류 · 경고 문구는 분명하게.** 삭제 확인, 권한 없음, 입력 오류처럼 실수하면 안 되는 문구는 세계관보다 정확성을 앞세운다.
4. **용어는 이 표에 있는 것만 쓴다.** 새 용어가 필요하면 이 표에 먼저 더한다.

### 2.2 핵심 용어 (확정)

| 내부 용어 (코드 · DB · 통합 명세) | 한채 용어 (화면) | 뜻 |
| --- | --- | --- |
| Platform / 홈 | **마을** | 여러 한채가 모여 있는 서비스 전체, 그리고 서비스 메인 화면 |
| Blog | **한채** | 회원 한 사람이 지은 집. 블로그 하나 |
| Blog Owner / 블로그 주인 | **주인** | 한채를 지은 회원 |
| Blog Creation / 블로그 개설 | **한채 짓기** | 회원이 자기 한채를 처음 만드는 것 |
| Blog Home / 블로그 메인 | **한채** (첫 화면은 **마당**) | 한채에 들어가면 처음 보이는 화면 |
| Category / 카테고리 | **방** | 한채를 구성하는 주제별 공간. 예: 개발방, 여행방 |
| Post / 글 | **글 · 기록** | 한채 안에 쌓이는 글. 목록 · 영역 이름은 "기록", 단건은 "글"로 불러도 된다 |
| Blog Visit | **한채 방문** | 다른 사람의 한채 화면에 들어가는 것 |
| Subscribe / 구독 | **이웃** | 다른 한채의 새 기록을 받아 보려고 맺는 관계. "이웃 맺기 · 이웃 끊기" |
| Guestbook / 방명록 | **방명록** | 방문객이 한채 주인에게 남기는 인사 |
| Profile | **주인 소개** | 한채 주인의 닉네임, 프로필 이미지, 소개 |
| Blog Settings / 블로그 관리 | **한채 관리** | 주인이 한채의 정보, 방, 기록, 댓글을 관리하는 공간 |

| 블로그 삭제 | **한채 허물기** | 한채를 없애는 것 (BLOG-07). 확인 창 문구는 "한채 삭제"로 분명하게 쓴다 |

### 2.4 그대로 쓰는 용어

댓글, 답글, 공감, 태그, 공유, 저장, 알림, 로그인, 로그아웃, 글쓰기, 수정, 삭제, 검색, 조회수, 대표 이미지, 임시저장은 바꾸지 않는다. 사용자가 이미 아는 말이고, 바꾸면 기능을 찾기 어려워진다.

> 통합 명세의 사용자 · 블로그 · 분류 · 소통 용어 정의(2장)는 이 문서에서도 그대로 유효하다. 이 장은 그 용어를 **화면에 어떻게 보여 줄지**만 정한다.

## 3. 선택 항목

통합 명세 7장의 8개 선택 항목에서 한채가 고른 방식이다.

| 번호 | 항목 | 한채의 선택 | 이유 · 비고 |
| --- | --- | --- | --- |
| 7.1 | 로그인 방식 | **이메일 + 소셜** | 팀 ERD 합의(2026-10-06)를 따른다. 소셜 제공사는 카카오 · 구글 · 네이버. 이전 버전(0.6)의 "소셜만"에서 바뀜 |

| 7.4 | 에디터 | **WYSIWYG** | 글쓰기에 익숙하지 않은 사람도 쓸 수 있게 한다. 기존 목업(`admin/write.html`)과 같은 방식 |
| 7.5 | 글 주소 형식 | **번호** (`/123`) | **한채마다 1부터 매기는 번호**를 쓴다. 지운 번호는 다시 쓰지 않는다. 한채마다 서브도메인이 따로 있으므로 `minju.한채도메인/1`처럼 주소가 짧고 자연스럽다. 팀 ERD(서비스 전체에서 고유한 번호)와 다르다 (9.3). ERD: `posts.post_no`, `blogs.last_post_no` |

| 7.8 | 확장 공개 범위 | **구독자 공개 → "이웃 공개"** | 이웃 개념과 바로 이어진다. 공개 범위는 "공개 / 이웃 공개 / 나만 보기" 세 가지 |

## 4. 디자인 방향

### 4.1 공간 흐름

동양풍 요소는 화면 곳곳에 붙이는 장식이 아니라, 사용자가 **지금 어디에 있는지**를 알려 주는 표지로 쓴다. 모든 화면은 아래 흐름 중 한 곳에 속한다.

```
마을 ──▶ 대문 ──▶ 마당 ──▶ 방 ──▶ 기록
(메인)   (한채 상단)  (한채 첫 화면)  (카테고리)  (글 상세)
```

| 공간 | 해당 화면 | 이 공간임을 알려 주는 요소 |
| --- | --- | --- |
| 마을 | SCR-01~04 | 처마가 이어진 헤더, 넓은 여백, 여러 한채의 기록 카드가 늘어선 배치 |
| 대문 | 모든 한채 화면 상단 | 기와 지붕 선, 나무 현판에 쓴 한채 이름(제목 글꼴), 주인 소개, 이웃 맺기 · 방명록 버튼 |
| 마당 | SCR-06 | 밝은 한지 바탕에 최근 기록이 놓인 넓은 영역 |
| 방 | SCR-07, 사이드바 | 창호 문살로 나뉜 방 안내. 지금 있는 방은 문이 열린 표시 |
| 기록 | SCR-09 | 족자처럼 위아래 축이 있는 제목 영역, 글 끝의 낙관(주인 도장) |

**위치 표시**: 한채 안의 모든 화면은 `마을 › ○○의 한채 › 개발방 › 글 제목` 형태로 현재 위치를 보여 준다.

### 4.3 색과 글꼴

실제 값과 쓰는 규칙은 디자인 시스템 「한채」(Claude 디자인 시스템 문서)에 둔다. 기존 목업(`css/common.css`)에서 출발했지만, 0.14에서 색을 기와집 색으로 바꿨다.

| 구분 | 방향 | 토큰 |
| --- | --- | --- |
| 기본 색 | **기와집의 색.** 하얀 회벽(바탕), 청회색 기와(처마 띠 · 주요 버튼 · 푸터), 푸른 기가 도는 먹색(글자), 짙은 적갈색 나무(현판 판 · 방 안내 틀). 초가집처럼 보이는 누런 황토색 · 밝은 갈색은 쓰지 않는다 | `hanji` `paper` `giwa` `meok` `wood` |

| 글꼴 | 로고만 수성혜정체, 큰 화면 문구(마을 어귀) · 현판 · 기록 제목은 Gugi, 기록 본문은 Noto Serif KR, 화면 글자(메뉴 · 버튼 · 목록)는 Pretendard. 붓글씨 계열(나눔붓글씨 등)은 가독성이 낮아 쓰지 않는다 | `logo` `display` `serif` `sans` |
| 모서리 · 간격 | 기본 모서리 4px, 동그라미는 프로필 사진에만. 버튼 · 입력창 높이 44px 이상 | `radius-md` `touch-target` |

### 4.4 연출

- **대문 열기 연출(기존 랜딩 목업)은 메인 화면에서 뺀다.** 마을 메인은 들어오자마자 기록을 보여 준다 (통합 명세 HOME-01, 글 노출이 목적).
- 대신 다른 한채에 처음 방문할 때 대문이 열리는 짧은 전환을 넣는 것을 검토한다. 넣는다면 1초 이내, 건너뛸 수 있게, 같은 한채는 다시 보여 주지 않는다. (2차, 9.2)
- 휴대폰 화면에서는 처마 · 기와 장식을 줄이고 기록 목록을 먼저 보여 준다 (통합 명세 8.4).

## 5. 화면 목록

### 5.1 설계 방향

- **마을(메인)이 서비스의 첫 화면이다.** 로그인하지 않은 나그네도 바로 마을에 들어와 기록을 읽을 수 있다. 별도 랜딩 화면은 두지 않는다.
- **마을은 지도가 아니라 목록이다.** 여러 한채의 기록을 한 화면에 최대한 많이 보여 주는 티스토리형 홈 구조를 그대로 쓰고, 영역 이름과 디자인만 마을로 바꾼다.
- **한채 안의 화면은 모두 같은 대문과 방 안내를 갖는다.** 마당, 방, 기록, 방명록 어디에 있어도 같은 한채 안이라는 것을 알 수 있다.
- **검색은 모든 화면의 헤더에서 쓸 수 있다.** 마을에서는 "마을에서 찾기", 한채 안에서는 "이 한채에서 찾기"가 기본이다.

### 5.3 마을 화면(SCR-01) 구성

마을은 **두 칸**이다. 왼쪽은 스크롤하며 읽는 기록이고, 오른쪽 사이드바는 스크롤해도 화면에 붙어 따라온다(sticky). 끝없이 내려야만 순위와 로그인을 볼 수 있던 불편을 없애려고, 짧고 자주 보는 것(로그인 · 순위)은 오른쪽에 고정하고 길게 쌓이는 것(골목 · 새 기록)은 왼쪽에 둔다.

| 위치 | 순서 | 영역 (화면 이름) | 보여 주는 내용 | 목적 | 기능 |
| --- | --- | --- | --- | --- | --- |
| 위 | — | 헤더 | 손글씨 로고(마을로), 마을에서 찾기. 비회원은 "로그인", 회원은 "내 한채 · 글쓰기" | 어디서든 검색하고 내 한채로 이동 | COM, SRCH-02 |
| 왼쪽 | 1 | 마을 어귀 | 한 줄 소개("한 사람, 한 채, 그 안의 기록"), "한채 짓기" 버튼, 창호 그림 | 서비스 콘셉트를 한눈에 알리고 한채 짓기로 이끈다 | AUTH-04, BLOG-01 |
| 왼쪽 | 2 | 골목 | 골목(주제) 탭을 바꾸면 해당 골목의 기록을 몇 개씩 보여 줌 | 관심사별로 다양한 기록 노출 | HOME-03 |
| 왼쪽 | 3 | 이웃 소식 | 로그인했고 이웃이 있을 때만: 이웃 한채의 새 기록 몇 개 + "더 보기" | 이웃 관계를 다시 방문으로 잇는다 | SUB-02 |
| 왼쪽 | 4 | 새 기록 | 마을 전체에 방금 올라온 공개 기록. 더 불러오기 | 새 기록에도 노출 기회 제공 | HOME-01 |
| 오른쪽 (고정) | 1 | 로그인 · 내 자리 | 비회원: "마을에 들어오세요" 안내, 로그인 버튼, 카카오 · 구글 · 네이버 로그인, 이메일 가입 링크. 회원: 프로필 · 내 한채 이름 · 이웃 수, "내 한채" · "글쓰기" 버튼, 내 정보 · 로그아웃 | 로그인과 내 한채로 가는 길을 항상 보이게 | AUTH-01, AUTH-02, AUTH-04 |
| 오른쪽 (고정) | 2 | 지금 많이 읽는 기록 | 최근 1시간 조회수 순위 10개 (번호, 제목, 한채 이름 — 사진 없이 한 줄씩). 정각마다 갱신. "○시 기준" 표시 | 지금 많이 읽히는 기록 노출 | HOME-02 |
| 오른쪽 (고정) | 3 | 북적이는 한채 | 최근 1시간 조회수 합계가 많은 한채 4곳 (작은 현판, 주인 · 이웃 수, 대표 기록). 누르면 그 한채 마당으로 | 한채 방문 · 이웃 맺기 유도 | HOME-04 |
| 아래 | — | 푸터 | 서비스 정보, 저작권, 공지 | | ADMIN-06 |

**고정 사이드바 규칙**

- 오른쪽 사이드바는 화면 위에서 16px 떨어진 자리에 붙어 따라온다. 사이드바가 화면보다 길면 사이드바 안에서만 따로 스크롤된다.
- 좁은 화면(900px 이하)에서는 고정을 풀고, 사이드바가 기록 목록 아래로 내려간다.

**결정 사항**

| 항목 | 결정 | 비고 |
| --- | --- | --- |
| 인기 기록 점수 기준 | **조회수** | 공감 · 댓글 가중치는 이후 확장 후보 |
| 집계 기간 | **최근 1시간** | 정각 기준 직전 60분의 조회수 |
| 갱신 방식 | **정각마다 계산해 저장** | 다음 정각까지 같은 순위를 보여 준다 |
| 북적이는 한채 기준 | **최근 1시간 그 한채 기록들의 조회수 합계** | 공개 기록이 없는 한채는 빠진다 (통합 명세 HOME-04) |
| 골목(주제) | **서비스가 정한 10개 목록에서 글마다 하나 선택** (고르지 않아도 됨) | 방(카테고리)과는 별개다. 선택 7.7, 목록은 9.2 |
| 조회수 중복 | **같은 방문자가 30분 안에 다시 열면 세지 않음** | 새로고침으로 순위를 올리는 것을 막는다 |
| 1시간 조회가 없을 때 | **24시간 기준 → 그것도 없으면 빈 상태** | "○시 기준" 옆에 어느 기준인지 표시 |
| 노출 개수 | **디자인 후 결정** | |

**결정에 따라 생기는 구현 조건**

- 조회 시각과 방문자 구분값을 기록해야 한다 (ERD `post_views.viewed_at`, `viewer_key`). 조회수 숫자 하나로는 "최근 1시간"을 셀 수 없다.
- 매 정각에 집계를 실행하는 예약 작업이 서버에 필요하다. 결과는 ERD `ranking_snapshots` · `ranking_entries`에 저장하고, 같은 정각의 결과는 하나만 둔다.

### 5.4 한채 화면(SCR-06~10, 21) 구성

한채 안의 모든 화면은 아래 틀을 공유한다.

```
┌────────────── 처마 · 기와 ──────────────┐
│ [현판] 민주의 한채            [이웃 맺기] [방명록] │  ← 대문
│ 주인 소개 한 줄 · 이웃 12                       │
├─────────────────────────┬──────────────────┤
│ 마을 › 민주의 한채 › 개발방   │ [방 안내]           │
│                         │  모든 기록 (24)     │
│   (마당 / 방 / 기록 / 방명록) │  개발방 (10)  ◀ 열림  │
│                         │  여행방 (8)         │
│                         │  일상방 (6)         │
│                         │  마루 (0) → 숨김    │
│                         │ [이 한채에서 찾기]    │
│                         │ [태그]              │
└─────────────────────────┴──────────────────┘
```

| 영역 | 내용 | 기능 |
| --- | --- | --- |
| 대문 | 현판(한채 이름), 주인 소개(프로필 이미지 · 닉네임 · 소개), 이웃 수, 이웃 맺기 버튼, 방명록 바로가기. 주인에게는 이웃 맺기 대신 "글쓰기 · 한채 관리" | BLOG-02, SUB-01·03, CMT-04 |
| 위치 표시 | `마을 › ○○의 한채 › 방 › 글` | 4.1 |
| 본문 영역 | 마당: 모든 방의 최근 기록 / 방: 그 방의 기록 / 기록: 글 상세 / 방명록: 인사 목록 | BLOG-03, CAT-02, POST-04, CMT-04 |
| 방 안내 | 모든 기록 → 방들(주인이 정한 순서) → 마루. 각 방의 기록 수. 지금 있는 방 표시 | BLOG-04, CAT-04 |
| 이 한채에서 찾기 | 한채 안 검색창 | SRCH-01 |
| 태그 | 이 한채에서 쓴 태그 목록 | TAG-03 |

**기록(SCR-09) 화면 추가 규칙**

- 제목 위에 "개발방에 쌓인 기록"처럼 이 기록이 놓인 방을 보여 주고, 누르면 그 방으로 간다.
- 글 끝에 주인의 낙관(프로필 이미지)과 닉네임을 두고, 그 아래 공감 · 공유 · 댓글 순서로 놓는다.
- 이전 · 다음 기록은 "이전 기록 / 다음 기록"으로 부른다 (POST-10).

**마당이 비어 있을 때**: 주인에게는 "아직 마당이 비어 있어요. 첫 기록을 남겨 보세요" + 글쓰기 버튼, 방문객에게는 "아직 기록이 없는 한채예요" + 마을로 돌아가기.

### 5.5 검색(SCR-02, SCR-21) 구성

| 항목 | 마을에서 찾기 (SCR-02, SRCH-02) | 이 한채에서 찾기 (SCR-21, SRCH-01) |
| --- | --- | --- |
| 진입 | 마을 헤더의 검색창 | 한채 방 안내의 검색창 |
| 대상 | 기록(제목 · 본문 · 태그), 한채(이름 · 소개) | 이 한채의 기록(제목 · 본문 · 태그) |
| 결과 구성 | "기록" 탭과 "한채" 탭, 결과 개수. 기록에는 어느 한채 · 어느 방의 기록인지 함께 표시 | 기록 목록, 결과 개수 |
| 정렬 | 정확도순 (기본), 최신순 | 최신순 |
| 결과 없음 | "마을에서 찾지 못했어요" + 지금 많이 읽는 기록 추천 | "이 한채에는 없는 기록이에요" + 마을에서 찾기로 다시 찾기 |
| 제외 | 공개 범위상 볼 수 없는 기록 (통합 명세 4.1) | 같음 |

### 7.15 한채에서 덧붙이는 규칙

통합 명세의 규칙에 더해 한채에서만 적용하는 규칙이다. 통합 명세와 부딪치지 않는다.

**BLOG-01 한채 짓기**

1. 회원당 한채는 하나다 (선택 7.2). 이미 한채가 있는 회원이 한채 짓기에 들어오면 자기 한채로 보낸다.
2. 입력 순서는 한채 주소(번지) → 한채 이름(현판) → 주인 소개(선택). 주소 칸 옆에 "주소는 지은 뒤 바꿀 수 없어요"를 보여 준다 (통합 명세 4.2).
3. 한채를 다 지으면 빈 마당으로 가고, 첫 기록을 남기도록 안내한다.
4. 처음 지은 한채에는 방이 없다. 기본 방을 만들어 두지 않는다 (통합 명세 CAT-01 ④는 자율 → 한채는 만들지 않음).

**BLOG-07 한채 허물기 · AUTH-06 탈퇴**

1. 한채를 허물면 그 한채의 기록이 함께 사라지고, 주소는 영구히 예약된다. 확인 창에는 "한채 삭제"와 "기록이 모두 사라짐"을 분명하게 쓴다.
2. 허문 뒤에는 다른 주소로 새 한채를 지을 수 있다. 회원당 살아 있는 한채는 언제나 하나다.
3. 탈퇴하면 그 회원의 한채를 허문다(①과 같음). 남의 기록에 단 댓글과 남의 한채에 남긴 방명록은 지우지 않고 작성자를 "떠난 사람"으로 보여 준다.

**BLOG-03 · BLOG-04 마당과 방 안내**

1. 한채 안의 모든 화면은 같은 대문과 방 안내를 보여 준다 (5.4).
2. 방 안내 순서는 "모든 기록 → 주인이 정한 방 순서 → 마루"다. 마루에 기록이 없으면 마루는 숨긴다.

**CAT-01 방**

1. 방 이름은 주인이 자유롭게 짓는다. 이름 끝에 "방"을 자동으로 붙이지 않는다 (예: "개발"이라고 지으면 "개발"로 보인다).
2. 방을 없애면 그 방의 기록은 마루로 옮겨진다는 것을 확인 창에서 알린다.

**SUB-01 이웃**

1. 이웃 맺기는 상대의 수락 없이 바로 된다. 자기 한채와는 이웃을 맺을 수 없다 (통합 명세 SUB-01).
2. 대문의 버튼은 "이웃 맺기 / 이웃" 두 상태로 보여 준다. 2차에 서로 이웃(SUB-05)을 만들면 네 상태로 늘린다.

**CMT-04 방명록**

1. 방명록 목록은 최신순이다. 각 인사에는 남긴 사람의 닉네임과 그 사람의 한채 바로가기를 보여 줘, 방명록에서 다시 다른 한채로 방문이 이어지게 한다.

**HOME-04 북적이는 한채**

1. 카드에는 한채 이름, 주인 닉네임, 이웃 수, 가장 많이 읽힌 기록 제목 하나를 보여 준다.
2. 누르면 그 한채의 마당으로 간다.

| 단계 | 이웃 맺기(SUB-01~03), 방명록(CMT-04), 북적이는 한채(HOME-04)를 1차로 앞당김 |
| 로그인 | 소셜만 → 이메일 + 소셜 (팀 ERD 합의) |
| 블로그 주소 | 경로 → 서브도메인 (팀 ERD 합의) |
| 글 주소 | 서비스 전체 고유 번호 → 한채마다 1부터 매기는 번호 (0.8) |
| 기준 ERD | Crowfoot 「한채 블로그 플랫폼」을 기준으로 쓴다. ERDCloud 사본(`Copy of blog.sql`)은 2차 기능(이웃 공개 외 닫힌 방, 답글, 저장, 알림, 신고, 방문 통계)을 만들 때 참고만 한다 (0.8) |
| 제외 | 블로그 꾸미기(BLOG-05)와 게임형 기능(가구 · 아이템 · 레벨 · 재화 · 아바타) 제외 |

### 9.2 결정 사항 (0.9)

0.8까지 미결정이던 항목이다. 기준 ERD(Crowfoot)의 요구사항에 이미 정해진 것은 그대로 따랐다.

| 항목 | 결정 | 근거 | 관련 |
| --- | --- | --- | --- |
| 소셜 로그인 제공사 | **카카오, 구글, 네이버** | ERD REQ-002 | 선택 7.1 |
| 골목(주제) 목록 | **10개 고정**: 일상, 여행·맛집, IT·개발, 문화·연예, 책·영화, 반려동물, 요리, 스포츠, 경제·재테크, 기타. 데이터 마이그레이션으로만 바꾼다 | ERD REQ-007 | POST-11, HOME-03 |
| 조회수 중복 | **같은 방문자가 30분 안에 다시 연 기록은 세지 않는다** | ERD REQ-008 | POST-09 |
